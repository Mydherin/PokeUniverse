**Writing a behavior (recipe):** find the template or task by name in FireRed's `src/battle_anim_*.c`, read its callback/OAM (`ObjBlend` → `blend: true`, `AffineNormal` → `affineNormal`, affine double → `affine`), write it from zero in the family file under the same name; spread it in `behaviors.ts`. Conventions: a task generator's code up to its first `yield` runs at creation (Cmd_createvisualtask calls it once), so a task whose C sets `func` without calling it starts with `yield`; a sprite's `init` is its creation call (CreateSpriteAndAnimate), use `runSprite(sprite, gen, done)` (first step at once) or set `sprite.callback`; sprites start at the target's picture (`run.center(Target)`); game palette masks via `util.selectedPalettes`/`paletteMask`; sounds play with an already adjusted pan: `run.play(se, run.pan(p))`; a task's own sprites: `run.createSprite(template, x, y, sub)` (not waited, destroyed at the end); a background task: `run.spawn(gen)`; extra art: `ART` + `TASK_ART`, read with `run.art(name)`. Check the expansion's C before its moves use a behavior.

**Coverage check:** a one-off `node` script over `firered.json` + `expansion.json`: walk each move's/general's reachable blocks (`label`, `first`/`second`), list templates/tasks not defined in `behaviors.ts` + `behaviors/*.ts` (match `^\s*\*?\s*(\w+)\s*[(:]`), tags not in `art.json`, BGs missing; count programs with nothing missing and rank the missing names (and "alone": the only thing missing).
